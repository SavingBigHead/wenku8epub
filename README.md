# 卷间 · 文库分卷 TXT ＋ mojimoon 排版 ＋ auto-novel 插图

流程：**从 dl.wenku8.com 下载分卷 TXT → 用 mojimoon 的 EPUB 生成器制作无图底稿 → 匹配同卷 auto-novel 插图 → 校对并插回底稿**。

正文、插图和排版分别处理。auto-novel 的机翻文字只用于定位，不写入最终正文；未旋转图片保持原始字节；旋转 JPEG 优先无损变换，无法无损变换时旋转像素并无损保存为 PNG；其他旋转位图无损保存为 PNG。

## 启动

项目使用 uv 管理环境，Python 固定为 3.14.8（.python-version），所有依赖的具体版本及校验值固定在 uv.lock。当前 Arch WSL 已安装 uv。

双击 start.cmd，或在 Arch WSL 项目目录运行：

~~~bash
uv sync --locked
uv run --locked run.py
~~~

打开 <http://127.0.0.1:8765>。换端口可以加 --port 8766。uv run 会自动检查并同步项目的 .venv，不需要手动激活环境。

换一台电脑时，先安装 [uv](https://docs.astral.sh/uv/getting-started/installation/)，再在项目目录执行上面的命令。uv 会在需要时下载固定版本的 Python 并安装锁定的依赖。Windows 原生环境也可执行相同的 uv 命令；start.cmd 是当前 Arch WSL 的快捷入口。

日常启动使用 --locked：如果依赖声明与锁文件不一致，会提示错误，不会自动更改锁定版本。主动升级依赖时运行 uv lock --upgrade，再运行 uv sync --locked 并验证。pyproject.toml、uv.lock 和 .python-version 应一同纳入版本管理；.venv 不提交。

## 生成无图底稿

在第一步填写小说 ID 或文库书籍链接、目录卷序号；也可以粘贴完整的 packtxt 下载链接。可选的「分卷 ID」用于手动指定 vid，留空则从目录取得。

- 正文固定从 https://dl.wenku8.com/packtxt.php 获取，携带 aid、vid、charset=utf-8。
- 作者、简介、标签、系列和章节目录来自文库详情页与在线目录。不再请求逐章阅读页，不按详情页的下架公告直接停止；是否生成取决于 TXT 接口实际有没有返回有效正文。
- 目录中的 vid 与首章 cid 可能不同。自动模式使用目录卷 ID，也支持手工填写该卷首章 ID。手动 vid／下载链接优先于卷序号，并校验其属于当前书籍。
- 目录序号仅用于选择文库目录中的第几本，包含短篇集和外传，不作为实际卷号。只有原卷名中已有「第几卷」时，才转换为至少两位的阿拉伯数字；「冰果」「短篇集」「外传」等不补卷号。原作第6.5卷显示为第06.5卷。
- 接口即使带 charset=utf-8，也可能返回带 BOM 的 UTF-16。程序先识别 BOM，再严格解码，避免乱码；错误网页、无效编码和空正文会报错。
- 按目录原始章节标题切分 TXT，支持带卷名前缀的标题。对不上或缺章时停止，不猜测切章。切章前还原 HTML 字符实体并删除独立的插图编号占位段落；另移除已识别的首尾站点包装，保留翻译来源等正文文字。
- 全程不下载封面或插图。简介页、CSS、正文由固定版本的上游 epub_maker.py 生成；适配层把两套目录改为同级，去掉扉页的重复卷号标题。空扉页不加入阅读顺序，但保留可插图的位置。

「仅保存 TXT」下载源站文本后，在保存前还原 HTML 字符实体（例如 `&#8231;` → `‧`、`&#x2027;` → `‧`、`&amp;` → `&`），并删除整段只有「插图001」「（插图001）」「【插图008】」这类编号占位标记的内容；兼容「插圖」、全角数字及标记前后空白，正文中提到插图的句子不会删除。保留原始编码、BOM、字节序和其余段落的缩进与换行，不先制作 EPUB。下载后也会把这份清理后的 TXT 填入本地转换入口，并带入文库目录位置作为系列卷号。

「从本地 TXT 生成无图 EPUB」可离线使用，不需要插图源。支持带 BOM 的 UTF-16、UTF-8 和 GBK／GB18030，可自动识别或手动指定。文库打包 TXT 按原有缩进和标题切章；普通 TXT 按常见章节标题切章。书名默认来自文件名，作者、简介、系列、系列卷号（阅读顺序）和标签可自行填写；本地 TXT 通常不包含这些书籍信息，不联网猜测。离线导入的 TXT 默认不猜测系列卷号，可按文库阅读顺序自行填写；在线下载后直接转换的 TXT 自动沿用文库目录位置。完成后使用同一份 mojimoon 排版生成器，生成底稿自动填入中文正文。

在线「生成无图底稿」与「从本地 TXT 生成无图 EPUB」使用和「仅保存 TXT」相同的文本清理规则：在识别章节前还原字符实体并删除独立的插图编号占位段落，保留正文中提到插图的句子、翻译来源和正常章节标题。在线生成命中旧 TXT 缓存时也会执行清理，不需要清空缓存；本地转换不会覆盖原 TXT 文件。

编码处理：TXT 缓存保存源站原始字节，不受保存或生成时的清理影响；「仅保存 TXT」对新下载和缓存命中的内容都会清理，并按原编码写出。生成 EPUB 时，读取后解码成 Unicode 文字，清理后再切章；mojimoon 生成 XHTML 时编码为 UTF-8，再打包为 EPUB。不会把 TXT 缓存或下载文件统一改成 UTF-8。

完成后底稿自动填入中文正文，也可单独下载。命令行示例：

~~~bash
uv run --locked generate.py --aid 1163 --volume 1
uv run --locked generate.py --aid 1163 --vid 35538
uv run --locked generate.py --aid 1163 --vid 35538 --format txt
uv run --locked generate.py --aid "https://dl.wenku8.com/packtxt.php?aid=1163&vid=35538&charset=utf-8"
~~~

输出为 out/text/小说ID/vNN.epub，旁边有卷索引 index.json。下载文件名使用实际书名与原卷名，仅对原有「第几卷」做数字格式转换；TXT 下载名采用同样规则。TXT 缓存独立保存在 out/cache/小说ID/packtxt/；目录与更新时间一致时复用，最长一天。旧逐章 HTML 缓存不再使用。

普通连接失败时可切换兼容连接。源站要求登录时可设置 WENKU8_COOKIE 环境变量或项目根目录的单行 COOKIE 文件；程序不会把 Cookie 写入校对项目。

## 匹配插图与章节归属

1. 导入同卷 auto-novel EPUB，优先选择含中文正文的中文／日中双语版。
2. 点击「开始匹配」，逐张检查用途：封面、卷首图、正文插图或忽略。
3. 用候选位置、正文搜索和章节跳转确定落点，确认后导出 EPUB。

**「本章开头」和「上一章结尾」是两个独立位置，不能因为它们在阅读顺序上相邻就合并：**

- 本章开头：写入本章 XHTML，位于章节标题之后、第一段正文之前。
- 本章结尾：写入该章 XHTML，位于最后一段正文之后。
- 普通段间位置：写入该段所在的章节。

mojimoon 底稿的原有分卷扉页也可插图：选中图片后点击「插入扉页」，或在章节列表选择标注「扉页」的页面，再选择「扉页开头」或「页面末尾」并确认。图片写入原有扉页，去掉扉页的重复卷号标题，目录项显示「插图」并仍指向原页面；可保存位置并载入项目恢复。空扉页在阅读顺序和目录中自动跳过，插入图片后恢复。普通 TXT／其他 EPUB 没有上游扉页时不显示此入口。

校对界面提供章首／章尾按钮；章节交界处会分别展示上一章结尾和下一章开头。自动匹配跨越章节边界时也保留两个候选，仍需人工确认。项目文件和合并记录保存确切的章节归属。

mojimoon 底稿通过在原始段落边界插图保留排版。CSS、未编辑的正文段落与未旋转图片字节不重写，简介页保留；修改书名、作者、标签或简介时会同步更新简介页。EPUB 3 导航目录与 EPUB 2 NCX 目录均改为同级，保留章节顺序和链接。扉页去掉重复的卷号标题，保留扉页插图及其他原有内容；没有内容的空扉页自动跳过。

TXT 和其他普通 EPUB 使用统一段落重排，其字体、加粗、超链接、ruby 和脚注跳转不保留。需要上游排版时，请使用第一步生成的 EPUB。

## 添加本地图片

「校对插图」右侧的「添加本地图片」可多选 JPEG、PNG、GIF、WebP。单张最多 20 MB，新增图片合计最多 40 MB，原插图与新增图片总数不超过 400 张。

新增图片进入同一个插图列表，可设为封面、卷首图、正文插图或忽略。未旋转图片保持原始字节；正文图片需人工选择扉页、章首、章尾或段后落点并确认。添加时默认沿用当前正文图的落点作为待确认位置；默认同一位置的图片按列表顺序写入，新增图片排在原插图之后；可在「同一位置的图片顺序」区用「上移」「下移」交叉排列原图与新增图片。选错的本地图片可点击「移除这张新增图片」。

校对项目 JSON 内嵌新增图片原始数据和 SHA-256，因此载入项目时无需再次选择本地图片。仍需导入同一组正文底稿与 auto-novel EPUB。项目最大 64 MB；未附带新增图片的旧项目仍可读取。

## 图片旋转

选中插图后，可在预览下方点击「左转90°」或「右转90°」，角度在 0°、90°、180°、270°之间循环。原插图和新增本地图片均可旋转；主预览、左侧缩略图和排序缩略图同步显示，不改变图片用途、落点、确认状态或顺序。「查看原图」仍打开未经过用户旋转的原图。

导出 EPUB 时，封面页、卷首图、扉页及正文插图会合并图片自身的 EXIF 方向与用户选择的角度，实际改变导出图片的方向，并使用普通图片标签显示。阅读器无需支持 SVG 旋转，书库封面也引用已旋转的图片；已有书库可能需要重新导入或刷新封面缓存。未旋转图片保持原始字节，原始文件、会话与校对项目中的图片始终不改动。

JPEG 优先使用 libjpeg-turbo 的 jpegtran 进行无损旋转，要求完整变换，不裁边；压缩块边界不满足条件、工具不可用、运行失败或超时时，自动旋转像素并无损保存为 PNG，不增加有损压缩；文件体积可能增加。当前 Arch WSL 已安装 jpegtran；其他环境需让该工具位于 PATH 中，否则直接使用回退路径。PNG／静态 GIF／静态 WebP 旋转后仍无损保存为 PNG，文件体积可能增加。

SVG 插图仍通过 SVG 展示层旋转，依赖阅读器的 SVG 支持。动图不能非零旋转导出，请换用静态图片或转回 0°；无法读取有效尺寸的图片也不能非零旋转导出。

校对项目中的每张图片以 rotation 保存顺时针角度，合并记录也列出角度。旧项目没有此字段时按 0°恢复；保存角度后请使用新版载入，旧版程序不识别旋转设置。撤销文字修改不会撤销之后调整的图片旋转。

## 图片排序

选中已定位的正文插图，在图片下方的「同一位置的图片顺序」中使用「上移」「下移」。该列表从上到下就是实际插入顺序，点击缩略图可查看对应图片。卷首图也有独立的排序区；封面与忽略的图片不参与排序。

排序只调整同一落点内的相对顺序，不修改用途、位置或已确认状态。「上一章结尾」和「本章开头」始终分开；旧项目的末段之后与该章结尾会识别为同一落点。左侧图片列表同步显示调整后的顺序。继续添加图片会保留已有排序，新图默认追加；移除本地图片会同时移除它的排序记录。

项目中的 image_order 保存全部图片 ID 的顺序，导出 EPUB 与合并记录均采用该顺序。没有该字段的旧项目沿用原来的顺序。

## 校对时编辑正文

在章节跳转列表选择章节，点击「修改章节标题」即可改名；标题不能为空，最多 300 字。章节跳转列表、正文中的章节说明和插图位置说明同步更新，导出时同时更新章节页面标题、正文标题、EPUB 3 目录与 EPUB 2 NCX 目录。正文段落、章节 ID 和插图落点保持原位置，已确认图片继续保持确认；空章节也可改名。扉页继续使用固定的「插图」目录项。

章节标题修改与段落操作共同使用「撤销文字修改」，保存校对项目会保存改名记录；载入同一组原始文件后恢复。撤销改名保留当前图片的位置与确认状态。

正文阅读区每段下方提供「修改」「前面添加」「后面添加」「删除」。新增段落也可以作为插图落点；空章节可重新添加段落。编辑框留空保存即可添加空段落，也可以把现有段落清空；空段落在校对区标注「空段落」，导出的 EPUB 显示为空行。空段落及其插图落点会随项目保存，删除整段仍需使用「删除」。编辑窗口先保存或取消，再继续定位图片。「撤销文字修改」可撤销本次打开工作区后的最近 30 次章节标题或段落操作；撤销段落操作时同时恢复该次修改之前的图片位置；载入项目后重新开始记录撤销历史。

增删改后，该章节中的正文插图需要重新确认。删除某张插图跟随的段落时，清除该图落点并提示重新定位，不自动转移到相邻章节。章首、章尾和扉页落点仍各自独立。

修改会随校对项目 JSON 保存并写入导出的 EPUB，不覆盖原始文件。恢复时先导入同一组原始文件，再载入项目；旧版无段落修改的项目仍可读取。保留 mojimoon 模式只改动所编辑的段落；未编辑段落、原样式、章节标题与未旋转图片字节继续保留。修改过的段落按普通文字保存，不支持输入 HTML 样式。

## 书籍信息

自动填写作者、系列和源站标签；系列卷号按文库目录位置从 1 开始连续填写，包含短篇集和外传，供阅读器按阅读顺序排列，与书名中的实际卷号无关。简介仅为文库目录中的第一本填写全书简介，第二本起留空。界面可查看修改，导出写入标准 EPUB 元数据及 Calibre 系列字段。这些字段供阅读器的「书籍信息」读取，简介页也继续保留。XML 使用与上游原版相同的默认 OPF 命名空间、dc: 字段和无前缀 meta 标签，兼容依赖常见标签写法的旧阅读器；不再把 package、metadata、meta 改写成 ns0: 标签。书名、下载名和分卷标题中原有的「第几卷」统一为至少两位阿拉伯数字：第01卷、第02卷、第06.5卷；不凭目录位置补卷号。本地 TXT 转换同样不默认追加「第01卷」。

是否为第一本按文库目录位置判断，与原卷名的实际卷号、下载先后和手动指定 vid 无关。正文中的「本卷简介」「内容简介」等章节仍原样保留，不再抽取为书籍简介。第二本起简介页和阅读器可读取的简介均留空，仍可手动填写。

## 匹配限制与进度保存

当前是字符二元组与文字序列相似度匹配，考虑 1～3 段窗口并约束插图顺序，未接入语义模型。意译、人名译法、繁简差异、删节会影响建议。分数不是准确率；正文插图都需要确认或忽略。仅日文 EPUB 不适合此版自动定位。

「确认全部已定位图片」包含低分建议；没有落点的仍需手动处理。图片只能插在段落之间。

保存校对项目会下载 JSON，其中有文件 SHA-256、元数据、图片用途与位置、章节标题修改，以及你增补／修改的段落文字与删除记录，不包含完整原书或原插图源；自行添加的图片会以原始数据内嵌保存。恢复时先导入同一组文件，再载入项目。新位置锚点可区别章首与章尾；旧的段后位置仍可读取。重新生成的底稿可能与旧项目指纹不同，应保留原始文件以便恢复。

输入文件在内存中最多保留最近 4 组，闲置 4 小时过期。底稿及缓存保存于 out/，导出由浏览器下载。服务只监听 127.0.0.1；生成需要访问文库，合并本地文件不联网。关闭服务前请保存校对项目。

## 验证与范围

每次处理一卷，每份输入最多 80 MB，最多 16000 段／400 张图片，EPUB 解压最多 350 MB。不支持 DRM、扫描版和固定版式。支持 JPEG／PNG／GIF／WebP 和简单自包含 SVG，阅读器兼容性可能不同。

~~~bash
uv run --locked python -m unittest discover -s tests -v
~~~

测试涵盖 TXT 编码、目录切章、有效正文与错误页、缓存、下架公告与下载源的独立处理、原排版及元数据保留、章首与章尾的章节文件归属、段落增删改／空章节／新增段落放图、项目恢复、候选区分及原图字节。已实际验证 1163《古典部》第一卷（手动首章 ID 与自动目录卷 ID）及 1213 第一卷可从新来源生成。未对全部书籍或所有阅读器作兼容性认证。
